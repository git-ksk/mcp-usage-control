# Code of Conduct

[English](CODE_OF_CONDUCT.md) | [日本語](CODE_OF_CONDUCT.ja.md)

## Our commitment

We want `mcp-usage-control` to be a constructive, technically rigorous, and welcoming open-source project.

Participants are expected to discuss ideas, code, tests, documentation, and incidents with respect. Technical disagreement is normal; personal attacks, harassment, intimidation, discrimination, and deliberate disruption are not acceptable.

## Expected behavior

- Critique implementations and assumptions, not people.
- Be specific about correctness, safety, reproducibility, and trade-offs.
- Assume good faith while still requiring evidence for security- or accounting-sensitive claims.
- Respect different experience levels, languages, backgrounds, and communication styles.
- Keep private vulnerability reports and confidential information private.
- Avoid publishing secrets, personal data, or production identifiers in issues, pull requests, logs, or examples.

## Unacceptable behavior

Examples include harassment, discriminatory or demeaning comments, threats, unwanted sexual attention, doxxing, deliberate disclosure of private vulnerability details, sustained trolling, and other conduct that makes participation unsafe or hostile.

## Scope

This policy applies in repository issues, pull requests, reviews, discussions related to this project, and other project-managed community spaces.

## Enforcement

Project maintainers may edit, hide, lock, or remove contributions that violate this policy and may restrict participation when necessary to protect the community.

If a conduct report itself contains a security vulnerability, credential, or other sensitive technical detail, use the private security-reporting path described in [SECURITY.md](SECURITY.md) rather than posting it publicly.

For ordinary conduct concerns, contact the repository maintainer through an appropriate private GitHub channel when available. Include only the information needed to understand the incident.

Enforcement decisions should be based on behavior and project safety, not disagreement over technical conclusions.
